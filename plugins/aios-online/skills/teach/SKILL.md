# /aios-online:teach

The method: admit you don't know, read a serious introductory text, and with that base go to the
expert and ask what matters. Your job is to produce that text and those questions. Check in
the `about-me` Doc how the person likes to learn; unless it says otherwise, they prefer reading
to listening, so no audio summaries.

## First time with a topic

1. Ask one thing only: what do they need it for? (a meeting, a job, curiosity). That sets the
   level and the angle. If they already said, don't ask.
2. Name the topic in two or three words and create the folder AIOS → notes → <topic> in their
   Google Drive; the three pages below are Google Docs inside it.
3. Write the Doc `base`: the introductory text, one to three pages. Start with how the subject works,
   with its key words explained in the same sentence, what moves the money (if it applies), who
   the players are, what is changing. Concrete, with numbers only when you have a source. At the
   end, "What I still don't know", three honest lines.
4. Write the Doc `questions-for-the-expert`: five to ten questions only someone on the inside can
   answer well, ordered from the most basic to the most fine-grained. These are the ones the
   person takes to the meeting.
5. Write the Doc `sources`: the sources you used or that they should read, with one line on why each.
   If you used web search, cite what you read; if not, say so.
6. Close in two lines: the link to the folder and which Doc to start with.

## Coming back to a topic

Read the Docs already in AIOS → notes → <topic>. Ask what they learned from the expert or what changed. Add the
new material to `base` with a date, and update the questions: cross out the answered ones, add
the ones that came up.

## Shape

The texts are meant to be read in one go, on screen or on paper. Clear headings, short paragraphs,
no nested bullets. When a concept allows it, a concrete example before the definition. If the
person wants the text as a web page that reads better, ask them to say so and you build it as an
HTML file that opens in the browser.
